① Recap: three ways to solve \(f(x)=0\)

Most non-linear equations have no closed-form solution, so we start from a guess and iterate until the change is below a tolerance \(\varepsilon\). Each method below has a full lesson on the Module 2 page — follow the links if something here feels unfamiliar.

Fixed-point iteration · lesson 2.1
\[ \text{rewrite } f(x)=0 \text{ as } x=g(x), \qquad x_{n+1}=g(x_n), \qquad \text{converges near } r \text{ if } |g'(r)|<1. \]
Bisection · lesson 2.2
\[ f(a)\,f(b)<0, \qquad c=\frac{a+b}{2}, \qquad \text{keep the half that still changes sign}, \qquad E_n=\frac{b-a}{2}. \]
Newton's method · lesson 2.3
\[ x_{n+1}=x_n-\frac{f(x_n)}{f'(x_n)}. \]
📏 The stopping rule used throughout
Stop when the error estimate is below the tolerance, \(E_n<\varepsilon\), or when a maximum number of iterations is reached — whichever comes first. For bisection \(E_n=\tfrac{b-a}{2}\); for fixed-point and Newton \(E_n=|x_{n+1}-x_n|\). The iteration cap protects you from methods that never converge.
MethodNeedsConvergenceGuaranteed?
Fixed-pointa good \(g(x)\)linear (error × \(|g'(r)|\) per step)only if \(|g'|<1\)
Bisectionbracket \([a,b]\)linear (error halves per step)✅ yes, if sign change
Newton\(f'\) + a good guessquadratic (digits ≈ double)no

② Worked examples

All three examples solve the same equation, \(f(x)=x^3-x-2=0\), whose only real root is \(r\approx1.52138\). Seeing one problem three ways makes the differences between the methods obvious.

💡 Predict the count in advance
The bound after \(n\) halvings is \(\tfrac{b_0-a_0}{2^{n}}\). With \(b_0-a_0=1\) and \(\varepsilon=0.01\) we need \(2^{n}>100\), i.e. \(n=7\) — exactly what the table shows. Bisection is the only method here whose iteration count you can compute before running it.

⚠️ Same equation, bad start
Start Newton at \(x_0=0.6\) instead. There \(f'(0.6)=0.08\) is almost zero (the curve is nearly flat at \(x=1/\sqrt3\approx0.577\)), so the tangent hits the axis far away: \(x_1\approx30.4\). The method does eventually crawl back, but needs 13 steps instead of 3. A near-zero \(f'\) is the classic way Newton goes wrong.

W3 · Fixed-point: a good \(g\) and a bad \(g\) partially worked

Solve \(x=e^{-x}\) (equivalently \(f(x)=x-e^{-x}=0\), root \(r\approx0.567143\)). The same equation can be rearranged in two ways:

Option A: \(g(x)=e^{-x}\)
\(g'(x)=-e^{-x}\), so \(|g'(r)|\approx0.567<1\) → converges.
Option B: \(g(x)=-\ln x\)
\(g'(x)=-1/x\), so \(|g'(r)|\approx1.76>1\) → diverges.

E1 · Turn bisection into a function

In class you ran bisection as a script. Turn it into a reusable function [root, n] = myBisect(f, a, b, tol, nmax) that returns the root estimate and the number of halvings. It must refuse to start if there is no sign change on \([a,b]\).

Reveal solution & output
MATLAB · myBisect.m (solution)
function [root, n] = myBisect(f, a, b, tol, nmax)
% MYBISECT  Root of f on [a,b] by bisection.
if f(a)*f(b) > 0
    error('f(a) and f(b) must have opposite signs');
end
n = 0;
while (b - a)/2 >= tol && n < nmax
    c = (a + b)/2;
    if f(a)*f(c) < 0,  b = c;  else  a = c;  end
    n = n + 1;
end
root = (a + b)/2;
end
Command Window output
root = 1.521380 after 19 halvings
Error using myBisect
f(a) and f(b) must have opposite signs

The loop stops when \((b-a)/2<10^{-6}\), i.e. \(1/2^{n+1}<10^{-6}\), which first happens at \(n=19\) (\(2^{20}\approx1.05\times10^{6}\)). The second call stops at the guard — without it, bisection would silently return a meaningless "root" near 2.

E2 · Newton as a function

Write [root, n] = myNewton(f, fp, x0, tol, nmax), where fp is the derivative. Stop when \(|x_{n+1}-x_n|<\) tol or after nmax steps. Then compare it with MATLAB's fzero.

Reveal solution & output
MATLAB · myNewton.m (solution)
function [root, n] = myNewton(f, fp, x0, tol, nmax)
% MYNEWTON  Root of f by Newton's method from initial value x0.
x = x0;
for n = 1:nmax
    xnew = x - f(x)/fp(x);         % Newton update
    if abs(xnew - x) < tol
        root = xnew;
        return
    end
    x = xnew;
end
root = x;                          % reached nmax without converging
end
Command Window output
myNewton = 1.5213797068 after 3 steps
fzero    = 1.5213797068

3 steps — the three rows of W2. From \(x_0=0.6\) the first step jumps to \(x_1\approx30.4\), and it takes 13 steps instead of 3 to come back: same method, same equation, only the initial value changed.

E3 · The convergence race

Run all three methods on \(x^3-x-2=0\) with the same tolerance \(10^{-8}\) and plot the true error \(|x_n-r|\) at every step on a log scale. For fixed-point use \(g(x)=(x+2)^{1/3}\) (from \(x^3=x+2\)). This script is complete — run it, then answer the questions below.

MATLAB · editable · race.m
Command Window output
iterations: bisection 26, fixed-point 9, Newton 4
Figure output
figure: error vs. iteration on a log scale — bisection (blue), fixed-point (green), Newton (red)
✏️ Read the plot
  1. Fixed-point gives a straight line on a log scale. What does that tell you about how the error shrinks? Estimate the factor per step from the plot and compare with \(g'(r)=\tfrac{1}{3(r+2)^{2/3}}\).
  2. Why is the bisection line jagged, even though its error bound halves every step?
  3. Why does the Newton curve get steeper every step instead of being straight?
Reveal answers
  1. A straight line on a log scale means the error is multiplied by the same factor every step — linear convergence. The line drops about one decade per 1.2 steps, a factor of ≈ 0.14, matching \(g'(r)=1/(3\cdot3.5214^{2/3})\approx0.144\).
  2. The bound \(\tfrac{b-a}{2}\) halves exactly, but the true error depends on where the root happens to sit in the bracket — sometimes the midpoint lands very close to it by luck (e.g. step 21), and the next step moves away again.
  3. Quadratic convergence: \(E_{n+1}\approx C\,E_n^{2}\), so the number of correct digits roughly doubles each step (\(3.6\times10^{-4}\to9.9\times10^{-8}\to7.5\times10^{-15}\)). The 4th error is exactly 0 in double precision, so semilogy cannot plot it.

E4 · Stretch: the bungee jumper optional

This is the opening problem of Chapra Ch. 5. A bungee jumper's velocity after \(t\) seconds of free fall is

\[ v(t)=\sqrt{\frac{g\,m}{c_d}}\;\tanh\!\left(\sqrt{\frac{g\,c_d}{m}}\;t\right), \qquad g=9.81\ \text{m/s}^2,\quad c_d=0.25\ \text{kg/m}. \]

What mass \(m\) makes the jumper reach \(v=36\) m/s after \(t=4\) s? You cannot solve for \(m\) algebraically — so write it as a root problem \(F(m)=v(4)-36=0\) and use your myBisect.

✏️ Your task
  • Define F as an anonymous function of m.
  • Find a bracket: evaluate F(50) and F(200) — do they have opposite signs?
  • Call myBisect(F, 50, 200, 1e-6, 100) and compare with fzero(F, [50 200]).
  • Why would Newton be less convenient here?
Reveal solution & output
MATLAB · bungee.m
g = 9.81;  cd = 0.25;  t = 4;  v = 36;
F = @(m) sqrt(g*m/cd) .* tanh(sqrt(g*cd./m)*t) - v;
fprintf('F(50) = %.4f,  F(200) = %.4f\n', F(50), F(200));
[m, n] = myBisect(F, 50, 200, 1e-6, 100);
fprintf('myBisect: m = %.4f kg after %d halvings\n', m, n);
fprintf('fzero:    m = %.4f kg\n', fzero(F, [50 200]));
Command Window output
F(50) = -4.5794,  F(200) = 0.8603
myBisect: m = 142.7376 kg after 27 halvings
fzero:    m = 142.7376 kg
m ≈ 142.74 kg

Newton would need \(F'(m)\), and differentiating this expression with respect to \(m\) by hand is messy and error-prone. Bisection only needs a bracket — which is why a derivative-free method is often the practical choice for "real" formulas. (Next week's secant method is another way around the derivative.)
